# 金标准范例库

作者（Task 2）写作前会通读**与当前标型最接近的一份范例**，模仿其质感与判断方式（火力分布、朴素章的分寸、确信的语气）。品味靠范例传递，规则只守底线——这里是整个 skill 的品味来源。

**当前状态：空。** 库为空时作者按 `writing-patterns.md` 品味一页写作，最终汇报如实标注"无范例校准"。

## 怎么添加范例

1. 一份范例 = 一个 `.md` 文件：**完整方案正文** +（推荐）文末**剖析页**（它好在哪、哪些章刻意朴素，对照 writing-patterns 六特征标注）。
2. 文件名按六大业务板块（见 `strategy-patterns.md`）：`video.md`（视频）、`social-media.md`（新媒体营销）、`brand-strategy.md`（全案品牌策划）、`event.md`（活动执行）、`space-design.md`（空间设计落地）、`graphic-design.md`（平面设计）。同板块多份用后缀区分（`event-发布会.md`）；跨板块的标取主板块范例。历史命名（creative-campaign 等）仍可被识别，但新增按板块命名。
3. 文件头用 HTML 注释声明来源与边界，二选一：
   - 真实案例：`<!-- 真实范例 · 来源：XX 项目（中标/客户好评）· 授权边界：内部教学用，客户名已脱敏/未脱敏 · 禁止逐字迁移 -->`
   - 合成范例：`<!-- 合成教学范例 · 客户与数据全部虚构 · 仅供质感模仿，禁止逐字迁移 -->`
4. 真实案例含敏感信息（客户名、真实报价、未授权数据）时先脱敏；范例只教质感，不当事实源（事实源在 `casebase/`，两者职责不同——casebase 管"真的发生过什么"，这里管"好方案长什么样"）。

## 防抄袭

范例启用后，定稿 lint 自动检查成稿与范例的 12 字以上连续重合：
`$PY tools/prop_tools.py lint-doc --doc <正文> --exemplar references/exemplars/<范例>.md`
命中即 error——作者只许学分寸，不许搬句子。
