# 案例库（casebase）

公司真实事实的**人工事实源**：写方案时的真底料，消灭"编团队、编设备、编案例"这类一票否决级虚构的地方。

## 轻格式（默认，够用为准）

- `公司事实.md`：公司基本盘/设备/团队/报价习惯/资质/打单习惯——按 `_快速填写模板.md` 填，一小时搞定。
- 一个案例一个 `.md`（如 `2025-某银行年会.md`），回答六问即可：
  1. 客户与项目（客户名可否露出：能/匿名/不能）
  2. 时间与金额区间
  3. 我方角色（总包/联合体/分包）与实际做了什么
  4. 最值得讲的一个细节（踩过的坑、救过的场、客户夸过的点）
  5. 可验证的结果（有出处的才写）
  6. 现场照片/成片/验收件在哪、找谁
- `_` 开头与 README 不作为案例；案例必须真实——虚构客户、合同、结果可能构成骗标。

## 重型溯源（仅在需要时升级）

案例要承担**资格证明、高风险业绩、公开数字、客户署名**时，才为该案例补重型字段：我方角色核验（prime/consortium/subcontract）、授权边界（客户名/Logo/评价/数字各自是否获授权）、核验状态（材料列出≠已核验，人工检查后才标 verified）、经授权的安全表述。老版 v2 全量 schema 在 git 历史，需要时取用。

原则不变：**列出不等于核验**；没有安全案例就明确缺口留待办，不用第三方案例或无核验文字顶替我方业绩；正文引用时案例只证明它真正能证明的范围（合同证参与、验收证被验收部分、截图证特定时点）。

## 质量教训（`_quality-lessons/`）

真实反馈驱动的品味资产：每次投标结果/客户批评回来后落一条（模板见该目录）。只有 human_confirmed 才提升进 `references/style-checklist.md` 或 `contrast-examples.md`。
