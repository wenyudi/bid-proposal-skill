# Task 1b — 创意锦标赛

一个方案 90% 的命运在创意收敛这一步就定了，文笔救不了平庸的创意。所以这里把最多的算力花在想创意上：并行发散 → 对抗淘汰 → 发展幸存者 → **用户从发展后的创意里选一个**。主 agent 按 `{ROLE}` 派发本文件，各 agent 只做自己角色的事。

占位变量：`{LANG}` · `{ROLE}` = ideate | kill | develop | onepager · `{JUDGMENT}`（**创意制胜标**：客户真话一页 + 真实采集成果 + 内行颗粒清单 + 硬约束——**不含评分表拆解**，创意在不知道评分表的语境里出生，floor 由编译期封标核对兜底；**管理制胜标**：`_研判.md` 拆解部分全文含评分拆解 + JSON 索引）· `{LIBRARY_CARDS}`（方案库参考卡集，可能为空；ideate 用它了解"库里同类标都怎么打的"——**照着卡里打法出的候选算普通候选，必须过互换测试**；kill 用它识别行业烂大街套路）· `{LENS}`（ideate 专用）· `{CANDIDATES}`（kill/develop 输入）· `{PICKED}`（onepager 输入：用户选中的 concept brief）· `{TMPDIR}`。

制胜轴适配：创意制胜标跑"创意锦标赛"；管理制胜标同一机制降档为"主张锦标赛"——镜头换成机制/可靠/成本结构/风险兜底，四问中"截图测试"换成"复述测试"（决策者能否一句话向上级转述）。混合标以主轴为准。

## ROLE = ideate（并行 6–10 个，各持一个镜头）

从 `{LENS}` 单一镜头出发（outcome / experience / asset / contrarian / 文化母题 / 地缘独占 / 行为摩擦 / 机制可靠……由主 agent 分配，一人一个），交 2–3 个候选创意。**只对本镜头负责，大胆、具体、别自我审查**——淘汰是 killer 的活，不是你的。

每个候选：
```json
{"idea": "一句话创意", "tension": "它回应客户的哪个真张力",
 "causal": "为什么这个创意能解这个张力（因果，不是愿景）",
 "sketch": ["可执行雏形：三个具体动作"],
 "sample": "一件成品示范——直接写一条能发布的内容（一句站点文案/一条帖子/一句旁白），演示创意跑起来的样子，不是描述",
 "monopoly": "独占依据——为什么换一家公司/换一个客户就不成立"}
```
返回 JSON 数组。禁止：行业通用套路（"打造矩阵""全域传播"）、没有独占依据的候选、写不出 sample 的候选（写不出成品的创意多半是空的）。

## ROLE = kill（并行 2–3 个，对全部候选投票）

对 `{CANDIDATES}` 逐个过五问，每问 0–2 分：
1. **互换测试**：换成竞争对手/换一座城市，这个创意还成立吗？（成立=0 分）
2. **截图测试**：普通人刷到会截图/转发/@朋友吗？（管理制胜标改问：决策者能否一句话向上级转述？）
3. **炫耀测试**：甲方（尤其宣传口）敢拿它向上炫耀、当标杆案例讲吗？评审翻十分钟能记住它吗？——机制再可信、炫不出去的候选压分（2026-08 轨道案教训：治理装置输给了写完的十站文案）。
4. **内行测试**：做过这行的人会觉得可行，还是笑话？（预算量级、审批、平台规则常识）
5. **兑现与硬约束**：会不会逼出无法兑现的承诺、撞上硬约束（预算/工期/内容红线）？（管理制胜标改问地板兼容：会不会伤合规覆盖？）

返回 JSON：每候选 `{"id", "scores": [n,n,n,n,n], "total", "verdict": "kill|keep", "one_line": "一句致命理由或最强价值"}`。**默认怀疑**：给分吝啬，keep 不超过 4 个。

## ROLE = develop（每个幸存创意一个 agent）

把幸存创意发展成一页 concept brief（Markdown，≤600 字）：
- 创意一句话 + 十秒记忆句候选
- 推导链：张力 → 创意 → 表达 → 执行 → 证明
- signature 设想（这个创意的"最清晰一页"长什么样）
- 三个最具体的执行动作（含责任/时点雏形）
- **最强反对理由**（自己写，写到能说服人放弃的程度）
- 需要哪些真实素材才能立住（对齐 Task 1 素材需求清单）

## ROLE = onepager（用户选定后，单个 agent）

以 `{PICKED}` 为准，产出完整制胜一页纸续写进 `{TMPDIR}/_研判.md`：
- 核心主张 + 十秒记忆句（逐字定稿）/ 推导链 / 打法（**管理标**：地板怎么保、天花板怎么顶；**创意标**：作品怎么立、拍板人拿什么向上炫耀）
- 被淘汰创意各留一句为何不选（含用户未选的发展稿）
- 逐章骨架表：章号 | 标题（句式多样）| 独有贡献 | 认领评分项 id（**仅管理标**；创意标此列留空，封标核对回填）| 深度取向 | 体裁基调(论证/表格/朴素) —— **章数由说服任务定，不由评分项数定**，常规标 5–8 章（2026-08 轨道教训：19 个 floor 撑出 13 章，输给对手 7 节；赢标案的章目录就是说服的节奏，不是应答的台账）。**创意标**：骨架只服从说服节奏，天然走向是"洞察 → 主意 → 作品 → 落地 → 凭什么是我们"（不强制照抄），**成品内容章放前排、拿最大篇幅**；巅峰章 = 作品章。**管理标**：floor 项多对一归章，打包类 floor 项归入"投标文件编制与递交"章；巅峰章 = 创意所在章，火力明显倾斜。**结构件（台账/准入/闸门类可信装置）各指定唯一宿主章，不做每章强制结构**——铺满全案就是把"怕错"写在每一页。
- **素材分配表**：每个论据/案例/数据/合规硬指标 → 唯一宿主章；合规硬指标指定底盘表宿主章
- 唯一 signature 主亮点（叙事与声线不再单独选型——由对应标型范例传递，作者写作时通读）
- **仅管理标**：回填 `_score-table.json` 各项的 `claimed_by_section`（创意标由编译期封标核对回填）

返回 JSON 索引（title / recall_line / narrative / signature / sections[] / open_fabrications[]），格式同 v4 Task 1 输出契约。

## 主 agent 编排（写在这里免查）
1. 按制胜轴选镜头并行派 ideate → 汇总候选（去重同质创意）。**按标定档**：常规标 4–6 镜头 / 2 killer（≥8 候选）；大标或用户要求充分发散时 8–10 镜头 / 3 killer（≥12 候选）。
2. 并行派 kill → 多数决合并，幸存 2–3 个（全灭则换镜头重发散一轮，最多两轮；仍全灭 → 如实告知用户"没有过硬创意"并展示最高分候选，不硬凑）。
3. 每个幸存者派 develop。
4. **唯一人工确认**：向用户展示客户真话一页 + 素材需求清单 + 2–3 份 concept brief（各含最强反对理由；管理标附评分表拆解摘要），问"按哪个写？"。`-auto` → 按 kill 总分自动选，登记 assumed。
5. 派 onepager 定稿一页纸。

## 完成判据
- 候选达档（常规 ≥8、大标 ≥12）、幸存 ≤3、每个幸存者有发展稿与最强反对理由。
- 用户（或 -auto）明确选中一个；一页纸各字段齐全；记忆句逐字定稿。
- **管理标**：每个评分项被且仅被一个合理章节认领。**创意标**：骨架为说服节奏、成品内容章前排、素材分配表齐全（评分项认领由封标核对完成）。
