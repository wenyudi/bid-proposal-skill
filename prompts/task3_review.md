# Task 3 — 制胜复核

主 agent 每轮并行派 3 个独立于 writer 的 agent，各执一个 lens。你会被告知自己是哪个 lens，只做那一个 lens 的事，返回结构化根因。**不改稿。**

占位变量：`{LANG}` · `{LENS}` = coverage | rival | client · `{REVIEW_BRIEF}`（一页纸 + 全文 + `_score-table.json` 或 floor 诉求清单 + 已合并的虚构申报）· `{TMPDIR}`。

## 交付目标
在正文里找出会丢分、减弱主张、或让方案变"普通/像给评委看的应答"的根因，让主 agent 精准升级弱章。宁可报可疑，也不放过"合规但空"。

## 依据与各 lens 的活
- **coverage（覆盖，内部核对）**：逐项对照 `_score-table.json`（无表用 floor 诉求清单），确认每个评分项在正文有明确、可定位的应答。漏项、只沾边、藏太深都算问题，按权重排序。
- **rival（制胜/对手视角）**：只看高权重（ceiling）章。对每处核心主张问"**换成竞争对手名称是否仍成立？**"——换了还成立 = 可互换 = 普通，是失败信号。专抓五类：①"合规但空"（覆盖了要求却没有对象/机制/依据/差异）；②"罗列而非价值"（团队/设备/案例只摆名单和参数，没讲对甲方意味着什么）；③ **假精确**——用编造的量化密度冒充履约证据：批量数字共用同一折扣率/公式（如全表 = 限价×0.88，计算器抽三行即戳穿）、小数点级的假"实测值"、成页的拟议仿真排程；④ **内行缺位**——以本行业内行视角问"这方案缺了哪些做过的人一定会写的东西"（投流预算与工具、刊例口径、审批归口、关键岗位角色、行业规范/色号），对照一页纸内行颗粒清单；⑤ **创意同构**——多个创意交付物是否共用同一模板（一个创意的 N 次换皮拿不到创意分）。读 `references/contrast-examples.md` + `references/anti-patterns.md` 校准。
- **client（客户体验）**：站甲方视角把**一切客户会看到的载体**读一遍——正文、综述，以及（若已生成）PPT 客户面字段（title/render_text/audience_takeaway/outline）与讲稿。查八件事：① **内部视角泄漏**——出现"评委/评标/评分/得分/满分/顶格/计 X 分/评分口径"或"不空承诺/有差异化"等自我点评，**以及内部定价规则与草案状态**（"按限价X%""暂按""待授权""补实件""非递交版""冻结版本"——报价的"怎么算出来的"是内部策略，客户面只给结论与可查验依据），即违 `references/writing-patterns.md` 递交禁项；② **口吻与声线**——是否自然、不打公文腔、不训话甲方（无道德审判句）、读出来不别扭；反向也查：**无人称报告腔**（通篇没有"我们"的担当句、没有对"贵方/您"说话的方向感，是没人在说话的说明文）与"本方案/这份方案"式文档自指；③ **包装**——能力是否讲成对甲方的价值，而非干巴罗列（名单/证书墙/长参数表），案例是否正向迁移而非连排自我否定；④ **主线与记忆句**——主线是否贯穿全章；**记忆句全文超过 2 次、或出现"这句话在本章的含义是"式逐章阐释，都是复读病**（出现处须逐字一致）；⑤ **文体与修辞密度**——同一句式/模板句是否用滥（"不是A而是B"刷屏、各章同款起手、标题清一色主张腔、四字排比命名成串）、加粗警句是否刷屏（每章 >3 处即报）、自我播报句（"条条硬""足以定案""值得摊开讲"）、双否免责连排、"贵行"当填充词、**段尾逐段升华**（"每一X，都Y"式点题收尾每章 >1 次）、段落节奏均匀无反差（连续等长段落无短句停顿）；⑥ **复读注水**——同一论据/案例/数字在多章完整重写、招标要求原文被逐章复抄、同构框架表逐章复制、章尾"本章已…/下一章将…"接力棒、综述或开篇的"第X章回答什么"式导览表、"见第X章"泛滥；⑦ **免责外显**——"拟议示例/不代表历史工单/须确认/待最终确认"式标注在正文成段出现，或"全案唯一主亮点"等脚手架词入文（免责属 `_风险与待核实.md`，不属递交稿）；⑧ **虚构漏报抽查**——对照素材，找正文里可疑地具体、却不在虚构申报里的事实。

## 工作顺序
1. 读 brief 和本 lens 对应的参考。
2. 按本 lens 逐章/逐项检查，定位到章节与句子。
3. 每条问题给：根因分类、位置、涉及评分项与权重（若相关）、一句诊断、建议修法。

## 输出契约
返回 JSON：
```json
{
  "lens": "client",
  "findings": [
    {"root_cause": "内部视角泄漏|口吻僵硬|罗列非价值|主线断裂|复读注水|修辞过密|免责外显|假精确|内行缺位|创意同构|虚构漏报", "where": "第三章 3.4",
     "diagnosis": "团队摆成姓名+证书表，没讲这几个人怎么替甲方守一致性", "fix": "改成三个角色的价值叙述，证书表降为附录佐证"}
  ],
  "clean": false
}
```
无问题时 `findings: []`, `clean: true`。

## 完成判据
- 只做本 lens 的事，findings 都定位到具体章节。
- coverage 覆盖 score-table 每一项；rival 覆盖每个高权重章、判五类（互换/罗列/假精确/内行缺位/创意同构）；client 走完八项检查并给漏报抽查结论。
