## 0. 一句话目标

停止用负面规则模拟品质，把生成架构重排到品质真正依赖的三种稀缺资源上：**真创意**（创意锦标赛）、**真素材**（真实优先）、**一个有品味的作者**（单作者 + 金标准范例 few-shot）；规则收缩为红线，品味交给范例。

## 1. 已拍板决策（实施中不得重开）

1. **范例来源**：先由本 skill 手工打造金标准范例（合成、非真实客户），**用户逐份审定后启用**；用户的真实优秀方案/赢标案后续补充替换。
2. **改造范围**：v5 重构主流程，先规格后实施；不做并行双轨。
3. 管"正确"的基础设施全部保留：评分表拆解、地板/天花板、响应对照索引、validate-index、风险登记、lint-doc、PPT 管线、封标检查表。它们不限制发挥。

## 2. 核心论点（为什么重构而不是继续补丁）

**完美创意方案的六特征**：① 一个"别人怎么没想到"的核心创意（事后显然、事前无人讲出、创意层过互换测试）；② 不均匀的火力（明显在赌那个创意，常规章朴素利落——火力分布本身是策略的可见形状）；③ 实证的质感（承重判断下有真地点、有出处的数字、活过的流程）；④ 一个人的声音（资深从业者对客户说话，敢说"我们不做 X 因为 Y"）；⑤ 阅读的节奏（有峰有谷，全文一两句让人记住）；⑥ 诚实但不自伤（风险住附录，信心住正文）。

**这六条没有一条能靠规则生成**。v4.6/4.7 的教训（实测，见 anti-patterns 两张病灶表）：每条负面规则修一个症状、造一个新伪影——禁雄辩体→无人称说明文；禁实名虚构→"一席某某账号"占位腔；禁免责成段→免责进图注。失败形态无限，规则只能划失败的边界。品味必须**给模型看**（范例携带数千条无法枚举的微观决策：节奏、何时用表、确信的分寸），规则只守底线。

**架构推论**：约束从生成侧撤到复核侧——writer/author 的 prompt 里只留红线与范例，密度红线、句式规则等全部只活在 review lens 与 lint（检查还在，枷锁不在）。

## 3. v5 主流程

### Step 0 摄入（不变）
Task 0 ingest + 素材卡机制照旧。

### Step 1 拆解与真实采集（task1 改造）
- 评分表拆解、地板/天花板、`_score-table.json` 机制不变。
- **真实优先**：把"研究补证"升级为独立动作——穷尽可查证的公开真实（实景图及授权、公开数据、平台规则、行业刊例、规范色号），逐条记出处；产出《素材需求清单》（哪些真素材能显著抬高方案上限、谁能提供）随确认展示给用户。虚构降为最后手段，四道闸门保留。
- 内行颗粒清单、素材分配表保留（它们是给作者的原料清单，不是枷锁）。

### Step 2 创意锦标赛（新，取代一页纸单遍收敛）
- **发散**：并行派 6–10 个低成本 ideation agent，各持一个镜头（outcome/experience/asset/contrarian/文化母题/地缘独占……），每个交 2–3 个候选创意（一句话 + 因果 + 可执行雏形），合计 ≥12 个。
- **淘汰**：并行对抗评审，每个候选过四问——创意层互换测试（换对手还成立？）、截图测试（普通人会截图转发这个吗？）、内行测试（做过的人觉得可行吗？）、地板兼容（不伤合规覆盖）。杀到剩 2–3 个。
- **发展**：幸存创意各发展成一页 concept brief（创意→表达→执行→证明的推导 + signature 设想）。
- **唯一人工确认改在这里**：把 2–3 个发展后的创意摆给用户选（含各自最强反对理由）；用户选中的才进入写作。`-auto` 时按淘汰赛得分自动选，登记 assumed。评分表拆解结果随创意一并展示（保持一次确认，不加仪式）。
- 管理制胜标（无创意分）：锦标赛降档为"主张锦标赛"，同一机制、镜头换成机制/可靠/成本结构。

### Step 3 单作者写作（取代并行 writer 拼装 + 主编终审）
- **作者 agent**（高推理、长上下文）通读：brief、`_研判.md`、素材与内行颗粒、**对应标型的金标准范例全文 + 剖析页**。范例声明：模仿质感与判断方式，禁止复用句子与结构套件。
- 作者先写**综述 + 巅峰章**（创意所在的 ceiling 章），确立声线与火力峰值。
- **常规章（floor/朴素章）可并行派 drafter**，但明确其产物是**素材性草稿**（事实、表格、逐项覆盖，不追求文采）；作者逐章改写进自己的声音，或直接采用（报价/资质类朴素即可）。虚构申报机制不变（drafter 与作者各自源头申报）。
- task2c 主编终审**取消**（单作者使其多余）；task2b 综述 prompt 并入作者职责。

### Step 4 复核（简化）
- 三 lens 保留：coverage 照旧；rival 增加"创意层复评"（成稿是否配得上选中的创意）；client 照旧。
- 循环 ≤2 轮，修复由**作者本人**执行（不重派陌生 writer——保住声音）。

### Step 5 编译与交付（不变）
lint-doc → 索引 → validate-index → PPT → 封标 → 汇报。lint 新增一项：与启用范例做 12+ 字连续重合检查（防逐字抄范例）。

## 4. 金标准范例库

- 位置：`references/exemplars/`（不能进 `casebase/` 非下划线区——那里会被当真实案例纳入）。
- 首批三份，对齐三份真实病例的标型：
  | 文件 | 标型 | 对应病例 |
  |:---|:---|:---|
  | `creative-campaign.md` | 创意传播/引流标 | 轨道 6 号线 |
  | `service-response.md` | 活动/服务技术响应标 | 贵宾营销 |
  | `production-framework.md` | 制作/印刷框架入围标 | 光大银行 |
- 每份 = **完整方案正文**（8k–15k 字，合成客户与数据，六特征全部做到位）+ **剖析页**（逐特征标注它好在哪、哪些段落体现、哪些地方刻意朴素）。
- 文件头声明：合成教学范例，非真实案例、非可复用文案；禁止逐字迁移。
- **制作与启用流程（STOP-1）**：本 skill 起草 → 用户逐份审定（品味校准，可批注改写）→ 审定通过才写入 `references/exemplars/` 并接入 Step 3；未审定的存 `.scratch/exemplar-drafts/`。
- 用户真实范例入库同路径，文件头改标来源与授权边界。

## 5. 规则删薄

- `references/writing-patterns.md` 收缩为三块：**硬红线**（真实性四闸门、递交稿禁项、编号规范）、**一页品味原则**（六特征的浓缩，指向范例）、指针（"质感看 exemplars，坏例看 anti-patterns"）。密度红线、句式轮换、节奏细则从生成侧删除，全部移入 task3 client lens 附录与 lint。
- prompts 相应减负：作者 prompt 的主体是"读范例 + 读原料 + 写"，不是规则清单。
- anti-patterns、contrast-examples 保持复核侧专用（生成侧不读，写作靠正面范例）。

## 8. 风险与对策

- **金标准品味风险**（范例本身不够好会污染全部输出）：STOP-1 用户审定是唯一闸门，宁可多改几轮。
- **逐字抄范例**：lint 12+ 字连续重合检查 + 范例头部禁令。
- **单作者成本/上下文**：作者只精写综述+巅峰章并改写其余（drafter 分担事实劳动）；上下文吃紧时按素材卡下钻，不通读一切。
- **锦标赛跑偏为"好句子比赛"**：淘汰四问全部指向创意本体（互换/截图/内行/地板），不评文笔。
- **标型无匹配范例**：取最近标型范例 + 剖析页通用部分，汇报中如实标注。
