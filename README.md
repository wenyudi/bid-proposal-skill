# proposal

面向广告与传媒公司的商业方案与投标方案生成 skill（v5）。给一批材料，产出一份成熟、有人味、客户可读的方案：创意从**锦标赛**里杀出来，正文由**一个作者**带着范例写成，有评分表时以评分表为骨架覆盖每一项，默认产出图片 PPT 结构稿交给下游图片工作流。

> 真创意 · 真素材 · 一个作者 · 范例传品味、规则守红线 · PPT 默认交接

## 它解决什么

- 一个方案 90% 的命运在创意上：**创意锦标赛**并行发散 ≥12 个候选，按互换/截图/内行/地板四问对抗淘汰，幸存创意发展成 concept brief（含最强反对理由）后由你拍板——这是全流程唯一一次人工确认。
- **真实优先**：先穷尽可查证公开事实（逐条带出处），并产《素材需求清单》告诉你哪些真素材能抬高上限；仍缺的才虚构，过四道闸门（实名不挂名、可查证不硬编、数字参差、免责不入正文），逐处申报进 `_风险与待核实.md`。
- **单作者写作**：drafter 只备料，全文声线、火力分布、节奏由一个作者负责——先写综述与巅峰章定调，再整合朴素章；`references/exemplars/` 的范例传递品味（lint 查 12 字重合防抄袭）。
- 有评分表时拆成**地板**（客观/mandatory）与**天花板**（高权重主观项），用**响应对照索引**证明覆盖。
- 独立于作者的**三-lens 复核**（覆盖 / 对手视角含创意层复评 / 客户体验按 style-checklist 走查），修复回作者本人。
- 默认**视觉分镜式**图片 PPT 结构稿（**完整商业稿**：缺真图用意向图顶位、内部字段绝不上屏、outline 带素材替换清单），交给图片工作流（image2 / kv-studio）。

v4 并行流水线在 tag `v4.7.0`；政企技术标重型引擎在 tag `v3.4.0-heavy`。

## 快速开始

要求 Python 3.8+（工具只用标准库）；运行宿主需具备文件读写、子 agent 和联网检索/抓取能力。新开会话，输入：

```text
/proposal /绝对路径/标书或brief.pdf /绝对路径/素材/
```

1. Task 1 拆评分表 + 真实采集；创意锦标赛发散淘汰后，你从 2–3 份发展稿里选一个（唯一一次确认）。
2. 作者带范例写全文 + 三-lens 复核后，定稿正文、响应对照索引与图片 PPT 结构稿一起产出。
3. 把 `_PPT生产包` 交给图片工作流做样张与逐页生成。
4. 递交前清零 `_风险与待核实.md` 里的高风险项，按《素材需求清单》补真素材。

## 常用调用

```text
/proposal <标书/brief 路径或粘贴文本> [素材路径] [-no-ppt] [-auto]
```

- 无深度/叙事旗标——永远尽力做到最好，叙事按标型自动选。
- `-no-ppt`：只出正文，不产 PPT 结构稿。
- `-auto`：跳过唯一人工确认，按淘汰赛得分自动选创意，产草案（assumed 决策阻断直接递交）。
- `casebase/` 中非 `_` 开头案例自动纳入；沟通/踏勘纪要标 `[notes]`。
- 素材可直接丢原始格式（doc/docx/ppt/pptx/pdf/扫描件）：Task 0 摄入本地解析 + OCR 兜底（MinerU / 百度 PaddleOCR-VL），密钥放 `~/.config/proposal/ocr.json`（仓库外，不入库）；资料多时并行产素材卡，Task 1 按图索骥不通读。

## 你会得到什么

```text
<方案标题>-<时间戳>/
├── 方案正文.md              客户可读递交稿
├── 响应对照索引.md          有评分表时；交付级
├── _PPT生产包/              outline.md + deck-blueprint.json + presentation-validation.json
├── _风险与待核实.md          内部：虚构/假设做实清单（权重×风险排序）
├── _封标检查表.md            内部：投标当日封装/递交执行清单（有封标类要求时）
├── _materials/              内部：素材摄入产物（manifest + 文本 + 素材卡）
├── _reviews/                内部：每轮复核 lens 结果
├── _研判.md                 内部：拆解、采集成果、锦标赛记录、一页纸
├── _score-table.json        内部：机器可读评分表
├── _draft.md                内部：作者工作稿
└── _sections/               内部：drafter 素材稿
```

`_` 开头文件不递交。

## 安全边界

proposal 不替投标人确认资质、业绩、报价、资源容量或保证性 KPI。缺失素材会被**具体虚构补全**以保持方案完整，但每处都登记在 `_风险与待核实.md`；这些占位在核实/替换前**不可直接递交**，最终汇报首句会明确提示。证据类图片（案例现场、资质、数据截图）永不生成，只走真实素材。
